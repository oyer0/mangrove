# Filesystem qualification

The Mangrove Filesystem Qualification Suite (MFQS) compares production
filesystem results with an independent Python byte/offset/namespace model.
The routine profiles qualify fixed and seeded MGFS, FAT32 and exFAT operations on
disposable regular-file images. This is a foundation, not complete filesystem,
storage, recovery, hardware or crash qualification.

## Production integration and boundaries

`tests/mfqs/runner.py` compiles complete, unmodified `kernel/src/vfs.c` and
the selected `kernel/src/storage/{mgfs,fat32,exfat}.c` translation unit with
ASan/UBSan. exFAT also links complete production `libc/src/time_convert.c`.
There is no
function extraction, source patching or replacement of filesystem allocation,
lookup, checksums, metadata publication, reclamation or recovery algorithms.
The adapter calls public VFS mount, ordinary/exclusive-create, open, read, write, seek,
metadata, checked enumeration, coherent streamed snapshots, conditional replacement,
truncate/resize, rename, unlink, mkdir/rmdir,
close and unmount APIs. Empty exclusive creation
exercises the actual recovery-pin registry and filesystem post-unlock handoff;
observations require zero outstanding pins after each operation.

`tests/mfqs/host.c` provides bounded host heap, regular-file block I/O,
single-threaded lock assertions and one immutable device descriptor. Process
context is the trusted kernel context with no working-directory references.
Credential and partition-specific callbacks abort if reached. These controlled
services do **not** test process authorization, scheduler synchronization,
block cache/registry races, partition management, DMA or physical devices.
Production VFS lifetime and recovery logic remain in use.
FAT32/exFAT flush callbacks perform actual host `fsync`. Raw formatter and
management callbacks abort if reached; independent tools prepare the images.
exFAT receives an explicit simulated trusted UTC clock at 2000-01-01 00:00:00
with whole-second precision. This neither detects RTC trust nor changes
production clock policy. Timestamp encoding/validation still runs in production.

A clean remount closes all file handles, invokes real VFS unmount/driver
disposal, verifies mount-private allocations were released and cached nodes
became inert, closes/syncs the image descriptor, reopens it, and mounts anew.
Readback then uses freshly discovered records. VFS intentionally retains
long-lived cached nodes after detach; the host releases only verified inert
nodes at final process exit and requires all other allocations to be gone.
This is host cleanup after production teardown, not a substitute for teardown.
Host `fsync` and image reopening do not establish target crash durability.

## Qualified profile and unsupported coverage

| Operation | MGFS fixed foundation | FAT32/exFAT fixed profiles |
| --- | --- | --- |
| Empty exclusive create; open/close/reopen | Covered | Covered |
| Ordinary public VFS creation | Not in the fixed trace | Covered separately from exclusive creation |
| Append, prefix/middle overwrite, zero-byte write | Covered, exact suffix/length preservation | Covered, exact suffix/length preservation |
| Seek/read/EOF and lengths/offsets | Covered | Covered, including zero-filled gaps |
| Root membership and missing/existing-name conflicts | Covered, case-sensitive ASCII names | Covered, ASCII case-insensitive conflicts and mixed-case opens |
| Clean remount and refusal with an open handle | Covered | Covered |
| Poisoned allocation slack and free clusters | Not in the fixed trace | Covered |
| DataLength greater than ValidDataLength | Not applicable | exFAT fragmented imported stream covered |
| Resize, safe replacement, rename, unlink, mkdir/rmdir | Fixed trace excludes these; generated coverage below | Fixed traces exclude these; generated coverage below |
| Broader imported layouts, Unicode, faults, concurrency, guest boot | Not qualified | Not qualified |

The MGFS trace retains its 98 commands and two successful remounts. It starts
with an empty MGFS 1.2 volume generated by the repository's `mkmgfs`, using
3,200 blocks, UUID `11111111-2222-3333-4444-555555555555`, and format time `1`.
It crosses inline storage, the 4 KiB boundary and the 8 KiB boundary, reaching
8,193 bytes. Byte patterns are independently specified in Python. Namespace
comparison ignores enumeration order but preserves duplicates and counts.
Structural checkers supplement the byte oracle; they cannot prove content safety.

FAT32/exFAT empty profiles contain 135 commands; imported profiles contain 167.
Each includes two successful remounts. FAT32 uses a standards-sized 64 MiB,
two-FAT volume with 512-byte clusters, built by `mkfs.fat --invariant` with
serial `12345678`. exFAT uses a 6,144,000-byte one-FAT volume with 4 KiB clusters,
built by `mkfs.exfat`. A bounded independent fixture encoder normalizes exFAT
serial/checksum fields and uses unknown utilization (0xFF), making the initial
image deterministic. It does not service any runtime filesystem operations.
All free clusters are poisoned with 0x5A. Imported allocated slack is 0xA5.

`--layout slack` imports `old.txt` with four readable bytes, then checks writes
at offsets 16 and 4196 against exact zero-gap expectations before and after
remount. exFAT additionally supports `chained-slack` (one-cluster FAT chain)
and `short-valid` (two nonadjacent clusters, DataLength 8000, ValidDataLength 4).
The latter's logical tail begins as zero despite poisoned storage and stays
correct when ValidDataLength advances. Imported dates are 2000-01-01 00:00:00;
exFAT encodes valid zero UTC offsets, while FAT32 has no timezone fields.
Images are independently checked before
production mounting and after teardown. This is a small fixed layout set,
not a general imported-image compatibility matrix.

Missing backend tooling or unsupported fixture layouts report **INCOMPLETE**
and exit 2. A model mismatch,
adapter failure, timeout or image-check failure reports **FAIL** and exits 1.
Successful execution satisfying the requested profile witnesses reports **PASS**
and exits 0, accompanied
by the explicit unqualified coverage list. Dependency, build and invalid replay
inputs report INCOMPLETE; they cannot become a green qualification result.
A correct but insufficient trace also reports INCOMPLETE (exit 2).
`execution_status` distinguishes successful execution from qualified coverage.
The broad qualification campaign remains incomplete even when this profile
passes. Existing recovery and storage regressions continue separately in the
normal host suite; MFQS does not replace or summarize them as its own coverage.

## Seeded lifecycle campaigns

`tests/mfqs/generator.py` generates valid operations from its own model, never
from filesystem observations. Every seed has a mandatory lifecycle spine:
ordinary and exclusive creation, empty-file growth, append, overwrite,
zero writes, truncate, nested directories, cross-directory file rename,
nonempty-rmdir refusal, exclusive collision, unlink, slot reuse, 255-byte ASCII
names, interleaved allocation/growth, and genuine remount. It then selects
16 namespace/content lifecycle actions for `quick` or 80 for `extended`, plus
16 or 128 content actions on a retained handle. Range selection mixes existing
boundary bias with rejection-sampled uniform valid offsets and lengths. The
mandatory sequence reaches exactly 65,535 and 65,536 bytes, performs overlapping
interior writes, shrinks and regrows, and crosses EOF. FAT32 additionally chooses
arbitrary resize lengths in 0..65,536; MGFS/exFAT keep their nonzero-resize exclusion.
Allocation interleaving targets fragmentation; actual placement remains driver-controlled.

Safe-file sequences use `vfs_file_create_exclusive` with nonempty initial contents,
`vfs_file_snapshot_stream`, `vfs_file_save_check`, and `vfs_file_replace`. A bounded
source copies immutable command bytes; it replaces no filesystem logic. Snapshot
chunks collect into a 64 KiB host buffer and are compared byte-for-byte with the
independent model. The adapter checks that the successful snapshot's identifier
and revision are bound to the retained handle. The model represents current/stale
save expectations, without predicting disk generation numbers. No-op resize
version advancement is deliberately unspecified: a snapshot is required before
an ensuing generation assertion. An ordinary content mutation must make the
old expectation stale; refused replacement preserves bytes and offset; a complete
snapshot rebinds it. Successful replacement refreshes its own expectation.
The lifecycle then performs ordinary mutation, rename, real remount and unlink.

### Qualification witnesses

`tests/mfqs/witnesses.py` derives witnesses from executed operations and observed
statuses/counts after independent comparison succeeds. HELLO and observation
commands do not count as mutations. Content mutations count nonempty confirmed
writes, nonempty exclusive creation, replacement with nonempty old or new contents, and
successful length-changing resize/truncate. Namespace mutations count separately.

Every fixed profile requires empty exclusive creation, append, contained
overwrite, zero write, EOF, namespace listing, successful remount, production
busy-unmount refusal, verified reopen, missing-open refusal and exclusive collision.
FAT32/exFAT also require ordinary creation and a zero-filled gap; imported profiles
require complete original-file readback before its contents are mutated.

Generated profiles additionally require directory STAT/type, mkdir/rmdir and
nonempty-rmdir refusal, rename/unlink/recreation, interior and EOF-crossing writes,
overlapping writes on one open handle, nonempty exclusive creation, coherent
snapshot, replacement, stale refusal and same-handle snapshot rebinding, the
ordered mixed safe lifecycle, exact 65,535/65,536 sizes and shrink from 65,536.
FAT32 requires nonzero resize grow/shrink; MGFS/exFAT require explicit UNSUPPORTED
nonzero resize instead. Unsupported outcomes never substitute for a supported
operation's success. Every substantive content mutation must have exact full
readback or a complete snapshot before another mutation erases that version.
Every successful remount requires complete readback of each surviving file
before its persisted version is mutated or deleted. The mixed lifecycle
requires this readback after its rename/remount and before retirement.
Extended profiles require at least 128 observed substantive content mutations.
Missing witnesses produce INCOMPLETE, including a HELLO-only replay labeled
as generated. Capability declarations and campaign labels cannot supply evidence.

Reports retain observed frequencies/statuses, mutation and verification counts,
distinct offsets/ranges, lengths, boundary sizes, required/present/missing witnesses,
and resource metrics. `qualified_behaviors` is empty unless qualification passes.
Open-handle REMOUNT actually calls production VFS unmount admission; there is
no adapter-only busy shortcut. Directory STAT checks existence/type; its size is
explicitly unqualified. LIST checks names and multiplicity, not entry types.
Unsupported oracle domains (directory handles/moves, wrong-type retirement,
file-as-parent traversal, and unmodeled LIST targets) report INCOMPLETE before
production execution rather than synthesizing incorrect expected filesystem errors.

After writes/resizes, exact reads check the whole affected file and EOF while
preserving its modeled offset. Namespace mutations immediately check the
relevant parent memberships. Close/reopen checks bytes again; full namespace
and content sweeps run every eight selected actions, with periodic and final
real teardown/remount. Expected lengths, contents, offsets and statuses are
computed before executing production code. No POSIX unlink-open semantics
are assumed: handles close before rename/unlink/rmdir. Directory moves and
open-handle namespace mutations remain unqualified.

The PRNG is SplitMix64 with explicit unsigned 64-bit wrapping. Each call adds
`0x9e3779b97f4a7c15`, applies xor-right-shift 30 and multiplication by
`0xbf58476d1ce4e5b9`, xor-right-shift 27 and multiplication by
`0x94d049bb133111eb`, then xor-right-shift 31. Seed-zero vectors are
`e220a8397b1dcdaf`, `6e789e6aa1b965f4`, `06c45d188009454f`,
`f88bb8a8724c81ec`. Selection rejects outputs outside the largest multiple
of the choice count below or equal to 2^64, then uses remainder. Payloads
consume one PRNG output per byte, taking its low eight bits. Candidate ordering
is specified or sorted; platform random, hash iteration, locale casing and
observed disk data never select expected content.

Routine regression runs quick seeds `0`, `1`, `0x5eed52` on every empty backend
and `0x5eed52` on every imported layout, with exact replay and generated
byte/length/namespace controls and observed-response offset/count/status/pin/
middle/tail controls. Extended seed `0x5eed54` runs and replays on every backend. The seven fixed profiles and both
historical production controls remain separate. Nonzero resize is exercised
through FAT32's internal hook; MGFS/exFAT must return UNSUPPORTED and preserve
contents and offset. MGFS sparse writes are not generated; FAT32/exFAT gap
writes require zeros. ASCII comparison is explicit per backend, not a substitute
for FAT32 Unicode or the volume's exFAT upcase table.

## Protocol, model and replay

`tests/mfqs/model.py` uses Python bytes and a pathname dictionary; it never
parses disk metadata or imports driver algorithms. Ordinary writes publish
`max(old length, written end)` and preserve unaffected bytes. FAT32/exFAT
gap writes add zero bytes; MGFS sparse writes remain outside its profile. The
fixed trace remains independent of the seeded generator.

MFQS1 requests are five tab-separated fields:
`MFQS1`, ascending sequence, operation, first argument, second argument.
Paths and payloads use lowercase hexadecimal; `-` represents an empty or
unused argument. Responses contain eight fields: version, sequence, VFS
status, file length, offset, transferred/type/member count, recovery-pin count,
and hexadecimal data. HELLO declares the backend/profile and differences in
name, gap and resize policy. FAT32's operation table supports arbitrary resize;
exFAT/MGFS support truncate-to-empty but reject nonzero arbitrary resize.
TRUNCATE sends zero length; RESIZE uses the internal handle resize route.
RENAME carries source and destination paths. LIST optionally names a directory;
omitting its argument preserves root enumeration. The generated/replay name
domain uses ASCII letters, digits, dots, underscores and hyphens (no trailing
dot), with a 255-byte component and 256-byte total-path harness bound.
CREATE uses exclusive empty creation; CREATE_CONTENTS carries up to 8 KiB of
initial contents; REPLACE carries up to 8 KiB through a bounded source callback.
SNAPSHOT returns complete contents (up to 64 KiB) without moving the offset;
CHECK reports the retained expectation's current/stale result. No native ABI
changes are made. CREATE_ORDINARY separately calls public
`vfs_create` and then `vfs_open_node`. STAT
and LIST return operation-specific metadata rather than active-handle offsets.
Malformed envelopes, reordered/missing responses and incomplete enumeration
cannot satisfy the model. Public VFS status constants are an ABI expectation,
not inferred from observed failures.
MFQS preserves raw VFS statuses, including UNSUPPORTED, UNCERTAIN and
TIME_UNAVAILABLE, instead of flattening them into a generic errno or EOF.
Unexpected refusal of an advertised operation is FAIL, not successful coverage.
The existing byte-count read interface still lacks detailed error classification;
the fault-free profile detects unexpected short content through its oracle.
ASCII membership comparisons normalize case only for FAT32/exFAT, retain
duplicate counts, and do not claim to qualify Unicode folding or name presentation.

Each run is bounded to 8,192 commands, one file handle, 8 KiB per input/ordinary-read transfer (64 KiB per complete snapshot),
64 KiB per file, 31 namespace objects, 64 MiB per image, 8 MiB requested kernel heap,
8,192 live heap allocations and 4,096 retained node slots. The adapter has a
120-second subprocess timeout; compiles have a 120-second timeout. Output
inspection is capped at 32 MiB; replay validation also bounds projected response
volume before creating media. These are harness bounds, not filesystem limits.
There is no automatic minimizer. The report identifies the first mismatching
operation and preserves the complete replayable trace and observations, plus
`failing-prefix.json` and `failing-prefix.tsv` ending at that operation. This is
the shortest observed failing prefix, not a minimized counterexample. Replay
uses the saved commands, never the generator or saved expectations; the seed
is provenance. Adapter stdout is flushed after each response to retain progress
on abort. Sanitizer diagnostics remain in `adapter.stderr`; UBSan is fatal.

## Commands and artifacts

On Linux use GCC and `make`; on macOS use native Homebrew GCC and `gmake`:

```sh
ASAN_OPTIONS=detect_leaks=0 make test-mfqs # gmake on macOS
python3 tests/mfqs/runner.py --cc gcc-16
python3 tests/mfqs/runner.py --cc gcc-16 --artifacts /tmp/mfqs-example
python3 tests/mfqs/runner.py --cc gcc-16 --replay /tmp/mfqs-example/report.json
python3 tests/mfqs/runner.py --cc gcc-16 --negative-control byte
python3 tests/mfqs/runner.py --cc gcc-16 --negative-control length
python3 tests/mfqs/runner.py --cc gcc-16 --backend fat32 --layout slack
python3 tests/mfqs/runner.py --cc gcc-16 --backend exfat --layout short-valid
ASAN_OPTIONS=detect_leaks=0 python3 tests/mfqs/runner.py --backend fat32 --campaign quick --seed 0x5eed52
ASAN_OPTIONS=detect_leaks=0 python3 tests/mfqs/runner.py --backend exfat --campaign extended --seed 0x5eed52 --artifacts /tmp/mfqs-extended
ASAN_OPTIONS=detect_leaks=0 python3 tests/mfqs/runner.py --replay /tmp/mfqs-extended/report.json
ASAN_OPTIONS=detect_leaks=0 python3 tests/mfqs/runner.py --campaign quick --negative-control namespace
```

An explicit artifact directory must be new. The CLI deletes its disposable
temporary directory only after PASS; FAIL/INCOMPLETE retain available evidence.
Artifacts include original and resulting images, commands, observations,
adapter stderr, first mismatch, complete expectations, source/binary/image
SHA-256 hashes, formatter arguments, compiler, platform and checkout identity.
Replay rebuilds the current production backend and regenerates the initial
image, requiring the original image hash to match. It recomputes the model
instead of trusting saved expectations. Negative controls must be requested
explicitly on replay; historical source requires its historical backend build.

FAT32 requires `mkfs.fat` and `fsck.fat`; exFAT requires regular-file-capable
`mkfs.exfat` and `fsck.exfat`. Tools are discovered on PATH and /usr/sbin.
Absent dependencies retain explicit per-backend INCOMPLETE results, and
`test-mfqs` returns failure rather than counting the backend as passed.
CLI compatibility adapters, where needed for exfat-utils, must be reported;
formatter commands/output and executable hashes are recorded in provenance.

`tests/mfqs_test.py` checks each positive profile, byte and length negative
controls, replay determinism, protocol rejection and visible missing-backend
reporting. It also compiles immutable historical MGFS commit
`487b9bdd6a536820c2f2ffcddcca691568c7de23` with the current VFS/host adapter:
the oracle detects its successful prefix overwrite shrinking 4,096 bytes to
one byte. Incorrect oracle-byte and oracle-length controls report FAIL even
though the resulting image passes structural checking. Regression-test PASS
means those failures were correctly detected, not that defective results passed.
The exFAT control similarly compiles immutable historical commit
`cb29138da7d20f1b0ea3cd96f86e6682d7752311`; writes return success with resolved
pins, but readback exposes poisoned slack at lengths 17 and 4197 and the model
reports FAIL. These controls require the historical commits to be available locally.

## Costs and portability

Measured on native Apple Silicon GCC with dosfstools 4.2 and exfat-utils 1.4
(its formatter CLI adapted to accept exfatprogs-style cluster-size arguments):

| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| MGFS empty | 98 | 242 | 45 | 0 | 104 | 95,824 bytes |
| FAT32 empty | 135 | 732 | 136 | 28 | 477 | 9,672 bytes |
| FAT32 slack | 167 | 895 | 192 | 34 | 556 | 9,808 bytes |
| exFAT empty | 135 | 621 | 125 | 56 | 125 | 23,460 bytes |
| exFAT slack | 167 | 741 | 157 | 66 | 146 | 24,372 bytes |
| exFAT chained-slack | 167 | 753 | 159 | 66 | 147 | 24,372 bytes |
| exFAT short-valid | 167 | 854 | 151 | 64 | 145 | 24,372 bytes |

After final unmount, 12 inert nodes (864 bytes) remain in the empty FAT32/exFAT
profiles and 15 (1,080 bytes) in imported profiles and MGFS; they are reaped at
exit. No transaction or driver-private allocations remain. Counts depend on
the initial layout/tooling and are measurements, not cross-filesystem budgets.
Driver calls can cover multiple sectors and are not
physical-device I/O counts. Reports include adapter CPU/wall time separately
from compilation and checker execution; timings are host-dependent.
Protocol, model and host-tool memory are outside the requested kernel heap.
Two image files are retained per artifact run: each is 13,107,200 bytes for
MGFS, 67,108,864 bytes for FAT32 or 6,144,000 bytes for exFAT. Fixture encoding
uses a bounded mmap and free-cluster inventory; it is outside the driver heap.
The regression releases image pairs only after all assertions for each case
succeed, retaining reports/traces/diagnostics until suite completion. Unexpected
failure media remains intact. A case and its replay can hold 256 MiB of FAT32
images; reports and subprocess/tool storage add to that peak. This avoids keeping
several GiB of already verified media in limited tmpfs storage. CLI runs only the
selected profile. FAT32's final checker can report an uninitialized free-cluster
summary because runtime transactions legitimately invalidate advisory FSInfo
hints; the checker exits zero and its warning is preserved, not suppressed.

Native Apple Silicon GCC ASan/UBSan runs without target-source adaptations.
The C adapter uses POSIX regular-file I/O and the build uses GCC on both
Darwin and Debian, with no platform-specific filesystem source changes or
GNU-only linker flags. Debian x86-64 fixed/generated ASan/UBSan campaigns,
independent checkers, the complete host suite and forced target build are
verified. The x86 `rdtsc` system-clock fixture compiles and passes here.
The seeded extension has not been executed on macOS ARM64; earlier fixed
profiles were verified there. The normal macOS host suite's
existing x86 `rdtsc` clock fixture cannot compile on ARM; this remains separate
from MFQS results. No guest/QEMU or hardware validation is implied.

Broader operations, independently imported
layouts, fault profiles and recovery
qualification require deliberate extensions with visible capability coverage.


### Seeded cost sample

Debian x86-64 GCC, empty layouts, extended seed `0x5eed54`, ASan/UBSan with
`ASAN_OPTIONS=detect_leaks=0`:

| --- | ---: | ---: | ---: | --- | ---: | ---: | ---: | ---: |
| MGFS | 2,535 | 197 | 120 | 15,004 / 1,589 / 0 | 3,184 | 132,832 | 1,567,144 | 0.558 s |
| FAT32 | 2,945 | 205 | 93 | 72,876 / 17,365 / 816 | 42,234 | 21,856 | 1,296,126 | 0.598 s |
| exFAT | 2,617 | 197 | 116 | 18,834 / 5,330 / 1,490 | 2,110 | 34,168 | 1,546,421 | 0.486 s |

All content mutations were independently verified. Timings exclude compilation,
formatting and checker costs. Requested heap excludes allocator/sanitizer overhead,
Python memory and adapter storage. Static allocation ledger, retired-node pointers
and snapshot transport buffer add 224 KiB on 64-bit hosts. MGFS reads 143,064
sectors and writes 12,712; FAT32/exFAT use one sector per driver call in this sample.
Final inactive nodes retain 45,432 / 7,200 / 6,192 bytes respectively, reaped at
process exit. Successful fault-free runs leave no unresolved transactions.
MGFS's zero driver flush count is an observation, not a durability assertion.
Comparator controls alter expectations or a separate response copy, never media
or driver callbacks. Pin-count controls demonstrate detection of a reported leak;
they do not inject an actual recovery object or establish leak-detection coverage.
Original observations and sanitizer output remain available alongside the corrupted
response copy and first failing prefix.

LeakSanitizer cannot run in the current ptrace sandbox; leak detection is
disabled explicitly. Requested-allocation teardown assertions are useful
lifetime checks, not a substitute for leak detection. Guest, hardware, reboot,
power-loss, concurrency and generalized fault qualification are not performed
by these campaigns. Large files, Unicode names, broader imported media and
broader safe-file limits remain separate coverage targets; passing this bounded
campaign does not qualify them.

Independent `mtype` readback of the FAT32 extended sample also matches the
model for all three surviving files in the maximum-seed extended campaign.
exfatprogs checks exFAT structure; it does not independently extract file bytes.


## Deferred engineering

Guest/native/Reed integration and realistic device behavior require guest qualification.
Concurrent and failure-injected lifecycle state machines remain separate work from
this fault-free suite and the existing focused recovery regressions. Unicode/imported
layout matrices, directory moves, multiple/open-handle namespace mutations and
sequential enumeration cursors are not generated. macOS ARM64 execution of the
expanded tester remains unverified.

The 2 MiB production safe-content and mapped-replacement limits, namespace-proof
budgets, directory limits, repeated scans/metadata I/O and retained recovery-memory
pressure need later filesystem engineering and pre-desktop resource acceptance.
The native 255-byte UTF-8 boundary needs future length-aware Unicode interfaces.
Runtime pins provide no crash atomicity or post-reboot repair; persistent recovery
and durability acceptance require separate design and verification. No completion
audits or guest/hardware experiments are implied by a profile PASS.
