# Native filesystem stress qualification

`fsstress` is an opt-in C17 application with a deterministic workload planner,
independent byte/namespace model and small native and POSIX adapters. It
complements [MFQS](filesystem-qualification.md): MFQS runs complete production
VFS/filesystem units with controlled host dependencies; fsstress runs ordinary
public native calls from a Ring 3 process in the real guest. Neither replaces
focused ownership, concurrency, recovery or malformed-media regressions.

## Build and use

```sh
make fsstress fsstress-host
make test-fsstress
# Host filesystem, new disposable directory and new trace file:
build/fsstress/fsstress-host run posix 5eed7 128 /tmp/stress-work /tmp/stress.trace
build/fsstress/fsstress-host replay /tmp/stress-replay /tmp/stress.trace
build/fsstress/fsstress-host verify /tmp/stress-work /tmp/stress.trace
```

The POSIX profile requires a case-sensitive host filesystem; a differently
configured volume needs its own declared capability profile.

The native executable is `build/fsstress/fsstress.elf`; it is deliberately absent
from normal release payloads. Install it explicitly in disposable guest media.
Native usage has the same arguments, with profile `mgfs`, `fat32` or `exfat` and
an authorized writable target parent. `ROOT` must be a new absolute path, at
most 160 ASCII bytes, with no dot components, repeated separators or trailing
separator. An existing root is an error, never a request to erase or repair it.
Trace saving is exclusive and precedes workload mutations. Keep traces outside
the workload root. Replay requires a fresh root; verify only reads an existing
workload and never recreates, repairs or overwrites expected files.

The native adapter binds the process CWD to the actual target parent and uses
relative, identity-anchored public pathname operations beneath it. Process exit
releases that location reference. It does not implement filesystem operations,
invoke privileged mounts, or replace authorization. Native snapshots,
conditional replacement and exclusive creation use the existing public APIs.

## Determinism and independent expectations

SplitMix64 uses unsigned 64-bit modular arithmetic, increment
`0x9e3779b97f4a7c15`, multipliers `0xbf58476d1ce4e5b9` and
`0x94d049bb133111eb`, and right shifts 30, 27 and 31. Bounded selection rejects
values below `(0 - bound) % bound` before taking the remainder. Payload bytes
are the low byte of successive outputs from a separate recorded operation tag.
Known-answer tests fix the generator and payload contract. No operation depends
on observed filesystem output, enumeration order, time or host integer width.

A mandatory lifecycle prefix is followed by seeded choices using both uniform
interior offsets/ranges and boundary-biased offsets. Sixteen equally selected
action classes include randomized directory creation/removal/moves; destinations
come from live model parents after bounded ancestry validation. Two directories
and the root remain available as parents while two have varying lifetimes. The action classes are write (four), read (two), zero truncate, file move,
unlink, reopen, snapshot, conditional replace, stale conflict, resize, directory
create/remove, and directory move. A missing selected file becomes an ordinary
create. Directory actions select from the two variable directory identities;
existing nonempty removal has its independently predicted refusal. Each actual
operation consumes one payload tag, including operations without payloads.
The prefix exercises
repeated overlapping/contained writes, append, EOF crossing, 512/4096-byte
boundaries, exact 64 KiB size, zero writes, truncate/regrowth, allocation reuse,
file rename/cross-directory move, a populated directory move, retained file
handles, nonempty-directory refusal, deletion/recreation and case probes.
Native profiles also require snapshots, conditional replacement, an independently
opened peer causing stale-save refusal, and nonempty exclusive creation/collision.
Deletion/recreation offers opportunities for allocation reuse; it does not
assert a particular physical placement. The model commits the peer's
independently generated bytes, then checks that
refusal of the stale handle preserved them. The stale intent has a flipped
first byte, or one byte `0xa5` when the peer saved an empty file, so an
incorrect write followed by a STALE return cannot hide behind identical bytes.

After every operation, the tool compares the complete directory tree and every
live file's exact type, length, identity and bytes, using fresh handles. It
checks read counts, EOF, zero reads and the retained handle's position. Listing
order is irrelevant; missing, extra, duplicate or wrongly typed entries fail.
Directory sizes are not modeled. Directory moves update ancestry independently
of filesystem lookup results. Deletion closes retained handles first; this is
not a claim of POSIX unlink-open semantics. One retained file handle and a
separate stale-save peer are exercised, not concurrent process stress.

`tests/fsstress_oracle.py` separately decodes traces and predicts statuses,
contents, paths and witnesses in Python. It does not call the C model or any
Mangrove filesystem code. The guest runner compares native traces with a
host-generated plan, validates every recorded operation/count/path/status, and
compares stopped media against this separate oracle.

### Capability profiles

| Behavior | MGFS | FAT32 / exFAT | Host POSIX |
| --- | --- | --- | --- |
| Shared ordinary lifecycle, zero truncate | Required | Required | Required |
| Write-created zero gaps | Excluded; no sparse writes | Required | Required |
| ASCII case-equivalent lookup | Must report missing | Must find same file | Must report missing |
| Public nonzero arbitrary resize | Explicit UNSUPPORTED | Explicit UNSUPPORTED | Supported |
| Coherent snapshot, conditional save, exclusive contents | Required | Required | Explicit UNSUPPORTED |

FAT32's internal VFS resize hook is not a public native syscall. POSIX mode does
not emulate native revision tokens or atomic save semantics. Names are bounded
ASCII long components, avoiding short-name display differences. Unicode,
normalization, OEM aliases and native long-name errors remain separately
qualified; generic locale casing is not used. Profiles must describe the
filesystem actually mounted; selecting a profile does not identify or mount it.
The guest supervisor checks actual device, filesystem, label and mount identity.

## Traces, evidence and failure results

The portable trace is `MGFSX001`, a 48-byte header followed by 32-byte records.
Fields use explicit little-endian encoding, not C structure layout. Header
fields record seed, profile, capabilities, count and control. A 64-bit FNV-1a
digest covers the entire encoding with its own field zeroed. Reserved fields,
lengths, bounds, domains and predicted statuses are checked before replay.
Replay executes recorded actions directly without invoking the generator.
`fsstress plan PROFILE HEXSEED OPERATIONS TRACE` produces a trace without
executing a workload, including plans for native profiles on the host.

`FSOP` records number, action, IDs, source/destination, range, payload tag,
expected/observed status and byte count. `FSFAILED` records the first failing
operation and shortest observed prefix. The runner saves that exact trace
prefix; automatic shrinking is not implemented. Transport faults remain explicit
runner configuration; replaying their logical prefix on healthy media does not
reproduce the transport failure. A prefix can be replayed even
when shorter than the generation minimum. A successful short replay lacking
mandatory witnesses is INCOMPLETE, never a qualified PASS.

Exit codes are 0 for completed qualification or requested persisted verification,
2 for INCOMPLETE (configuration, trace, capabilities, resource or time bound),
43 for a mismatch, and 44 for uncertain workload mutation. Trace load/save
failures leave the campaign INCOMPLETE and report the actual native status; the
workload has not begun. Filesystem recovery ownership remains independent of
the application exit code. Resource exhaustion is
not classified as filesystem corruption. Confirmed short I/O is distinguished
from an uncertain result; healthy bounded campaigns require the specified exact
counts. After failure, the tool closes handles but does not retry mutation,
unlink artifacts, repair metadata or discard recovery ownership. Existing
filesystem/VFS recovery contracts retain uncertainty.

Campaign PASS requires at least 64 operations, twelve substantive content
mutations, all mandatory supported action witnesses and all required range
witnesses. Unsupported actions are logged but never satisfy those witnesses.
`FSVERIFIED` is a read-only check, not evidence that a campaign executed.
The runner additionally requires genuine child spawn/wait/close/status,
complete transcripts, exact observed witnesses, expected volume operations and
zero remaining selected-volume owners on clean paths. Parent/child output may
interleave; child completion must precede successful wait evidence.

## Guest acceptance

```sh
make test-guest-stress \
  GUEST_STRESS_BUILD="$PWD/build/guest-stress-build" \
  GUEST_STRESS_OUTPUT="$PWD/build/guest-stress-results"
```

The output must not exist. Default campaigns use fixed seed zero and a generated,
recorded 64-bit seed, 96 operations per backend, two cold boots per campaign,
wrong-content controls on each backend, and additional MGFS oracle/fault controls.
The Python entry point accepts explicit repeatable `--seed` values, one backend,
64–256 operations and bounded timeout. Native standalone generation permits
64–1024 operations. Retain the report's seeds and traces for exact reproduction.
Dependencies and firmware are those of [secondary-volume qualification](guest-secondary-volumes.md).

The runner reuses its isolated Q35/OVMF/one-vCPU/512 MiB/xHCI USB topology, normal
login, Shoot, deviced, volumed and authorized native lifecycle. Boot/root and
secondary GPT media and firmware variables are private. exFAT uses the isolated
UTC-trusted build and explicitly UTC QEMU RTC. `fstest` only supervises discovery,
child lifetime and authorized owner inspection/unmount; the standalone child
owns the workload and model. No test-only kernel route is installed.

First boot creates and exactly checks the workload. The secondary is confirmed
unmounted before termination. Second boot uses the same images without
repopulation or repair, verifies the original, replays the recorded trace into
a fresh root and verifies that root with another child. After QEMU stops, MGFS
uses independent mgfsck and Record/extent decoding; FAT32 uses fsck.fat and mtools;
exFAT uses fsck.exfat and the existing bounded independent stream reader. The
reader rejects unsupported layouts. No host inspection occurs while QEMU can
write to the backing media. ACPI poweroff is not global VFS quiescence; confirmed
secondary unmount is distinct from system-root shutdown or power-loss safety.

Controls include persisted middle-byte corruption, deliberately wrong model
bytes, wrong expected status, exact replay of the failing six-operation prefix,
and a valid one-operation trace that must return INCOMPLETE. Host parser controls
reject missing/malformed/out-of-order completion, wrong paths/counts/witnesses,
device identity errors and unknown output. These parser fixtures do not constitute
guest evidence. Host controlled transport tests use real POSIX I/O to distinguish
short, failed, uncertain, no-memory/no-space and online-read errors.

Actual MGFS QEMU write and flush controls arm a one-shot blkdebug error before
launching the child, after an explicit readiness handshake and zero-write/flush
counter check. The first root-directory mutation must report UNCERTAIN; authorized
inspection must find its selected/physical-device UNRESOLVED owner after child
exit, and actual unmount must return BUSY. Images, checksums, checker output and
QMP counters are retained without repair. These are representative deterministic
faults, not an exhaustive randomized fault campaign across every filesystem.

## Resource bounds and remaining qualification

The core requests three allocations: a 655,664-byte execution/model object,
32,792-byte plan and 32,816-byte maximum trace buffer, totaling 721,272 requested
bytes on the qualified 64-bit build. This excludes allocator bookkeeping, libc,
stack and filesystem transaction memory. At most eight 64 KiB file bodies and
four directories are modeled. Paths fit 256 bytes with four directory ancestors;
trace size is at most 32,816 bytes. Output is bounded by 1024 operation records
and diagnostics, less than 1 MiB with maximum paths. Full sweeps deliberately
trade I/O for immediate detection, costing O(operations × live modeled bytes).
The tool prints check/mutation counts and elapsed time; the runner records QMP
backend read/write/flush counters, host CPU/RSS and artifact sizes. These are not
kernel heap peaks or filesystem-driver sector-call counts.

A representative 96-operation, seed-zero run on Debian x86-64 with parallel
TCG guests produced the following measurements. Backend counts cover the whole
creation boot, including discovery and supervisor operations; elapsed time is
reported by the workload, not total boot wall time. They are workload costs,
not performance guarantees or filesystem-driver sector counts.

| Backend | Exact checks | Content mutations | Workload milliseconds | Backend reads / writes / flushes |
| --- | ---: | ---: | ---: | ---: |
| MGFS | 4,866 | 31 | 37,689 | 640 / 547 / 83 |
| FAT32 | 4,342 | 31 | 63,569 | 10,797 / 3,727 / 176 |
| exFAT | 4,342 | 31 | 45,420 | 9,274 / 1,794 / 455 |

For the complete host suite, use a disk-backed `TMPDIR` when `/tmp` cannot hold
its independent image fixtures; disabling leak detection does not reduce those
media requirements. Native process peak heap and kernel transaction peaks are
not inferred from the core allocation bound or the Python runner's RSS.

The cooperative 180-second deadline is checked between operations; it cannot
interrupt a blocked syscall. The outer guest runner bounds each boot at at most
600 seconds, preserves failures, and rejects timeouts. Reserve 2 GiB artifact
capacity per seeded campaign and each extra control (default admission: 24 GiB).
Successful media and failure evidence are retained; no automatic repair runs.

Qualification remains single-process and single-vCPU with bounded small files,
healthy media except the explicit controls, and ASCII namespace. It does not
establish hardware, SMP, macOS, leak detection, active-I/O hot removal, persistent
recovery or power-loss durability. Existing safe-content limits, namespace proof
budgets, FAT metadata amplification and exFAT retained transaction limits remain
unchanged. Larger-file/scalability work, broader Unicode interfaces, concurrent
state machines and exhaustive interruption campaigns remain separate engineering.
